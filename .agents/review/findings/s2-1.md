# s2-1: Internal links resolve against predicted paths, so duplicate titles redirect them

## Evidence
`crates/cli/src/scrivener/converter/mod.rs`: the pre-pass `build_uuid_map`
predicts each item's path with `slugify`; conversion then allocates unique
paths with `unique_slug`. Text items overwrite their prediction with the
actual path, but folder aliases (a folder links to its first text child)
and attachments keep the prediction. Slice 2 moved every non-Draft root
under `research/`, so same-titled items from different roots now share a
folder and collide more often.

## Predicted observable failure
A root PDF and a Research PDF both titled "Scan" land at `research/scan.pdf`
and `research/scan-1.pdf`; links to either point at `research/scan.pdf`.
Characters/Hero and Research/Notes/Hero: Notes' child becomes
`research/hero-1.md`, but a link to the Notes folder still points at
`research/hero.md`, the character sketch. No warning either time.

## Approach
Record actual destinations: attachments map their UUID to the path the
conversion chose; a folder without its own text maps to the actual path of
its first text descendant, looked up after that descendant was converted.
Links are rewritten after conversion, so they see the final paths.

## Guard proof

Notes folder; every link names a distinct existing file and the folder
link reaches its own first document. With the actual-path updates removed
the test fails; restored, it passes; the suite is 67/67; clippy clean.
