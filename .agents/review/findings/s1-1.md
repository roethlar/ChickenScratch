## Evidence
`crates/cli/src/scrivener/parser/rtf_prepare.rs` control-word branch and
`rtf_text.rs` control-word branch: after `\uN` the pending fallback count
is left untouched when a control word follows, so `舑\endash word`
copies `\endash` and then swallows `w` as the "fallback". Both parsers.

## Predicted observable failure
`{\rtf1\ansi\uc1 a舑\endash word}` imports as `a––ord` (Pandoc path,
after preparation) and the fallback path loses the same letter. Reproduced
by the reviewer; the letter survives unprepared Pandoc.

## Approach
A control word or symbol that stands for a character (`\endash`, `\emdash`,
`\lquote`, `\rquote`, `\ldblquote`, `\rdblquote`, `\bullet`, `\tab`, `\~`,
`\-`, `\_`) counts as one fallback item and is swallowed like a `\'xx`
escape. Any other control word (formatting) ends the fallback run instead,
so a later letter can never be eaten. Same rule in both parsers.

Comments: the `a––ord` failure is fixed, but "any other control word ends
the fallback run" regresses `{\uc2 caf\u233\b e} noir`: the spec counts
every control word or symbol as one fallback item, so `\b` is item one
and `e` item two; the fix left `e` visible (`cafée noir`, both paths;
the parent gave `café noir`). Better approach: consume each control token
as one pending fallback item without applying it, keep the remaining
count.

**Disposition: ADMITTED.** Repair: every control word or symbol while a
fallback is pending is one item, swallowed and not applied — except `\u`
and `\uc` (they begin a new Unicode sequence; a writer never uses them as
fallback) and `\*` (structural; it ends the run and is kept so the group it
opens stays intact). Tests gain the `\uc2 … \b e` case in both parsers.
