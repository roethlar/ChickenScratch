# s3-1: Encoded fragments stop resolving after an editor save

**Severity**: MEDIUM — accented or otherwise encoded fragments lose working links after any save
**Status**: In progress — fixed, repair review pending
**Branch**: — (default-branch mode: one finding ↔ one commit on `master`)
**Commit**: `253a706` (fix) and `9610be0` (its guard test, which the fix commit lacked: the test edit had missed the reformatted file and the proof run matched no test); repair `0d403a1` after repair review 1; repair `b4e6e77` after repair review 2

## Evidence
`crates/core/src/core/compile_links.rs` `classify` (the fragment is taken verbatim). The editor writes `[Café](b.md#café)` as `[Café](b.md#caf%C3%A9)`; compile percent-decodes only the path part, then compares `caf%C3%A9` with Pandoc's identifier `café` and finds nothing: the link becomes text with a warning. An encoded bare fragment (`#caf%C3%A9`) is not matched to its element either, so the element is renamed and the link dangles.

## Approach
Percent-decode the fragment as well as the path before every lookup, in the duplicate count and in bare-target matching.

## Files changed
Declared before repair: `crates/core/src/core/compile_links.rs`, `crates/core/tests/compile_links.rs`. Repairs: the same two files.

## Guard proof
`percent_encoded_fragments_resolve_like_their_decoded_form` (crates/core/tests/compile_links.rs) fails with the fragment left undecoded (`Some(target[i + 1..].to_string())` in `classify`); 1 failed, restored → 9 passed.

Repair `b4e6e77`: the kept-duplicate set holds each bare fragment as written and decoded, and a bare link matches an element by either form. `literal_percent_identifiers_are_kept_and_followed_too` (duplicated `{id="caf%C3%A9"}` both kept with the link left as written; a unique one followed to its new name) fails with the decoded form alone (`both literal duplicates keep their string`), exit 101; restored → 16 integration and 7 unit tests passed, core clippy and fmt clean.

Repair `0d403a1`: `encoded_bare_links_keep_duplicated_identifiers` fails with the kept-duplicate set built from raw fragments (`map(|s| s.to_string())` for `bare_targets`): "assertion `left == right` failed: both duplicates keep `café`", exit 101; restored → 14 passed, core clippy and fmt clean.
