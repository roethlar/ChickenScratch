# s3-1: Opening the Inspector on a selected document can wipe its metadata

**Severity**: HIGH — saved notes (and, by the same path, synopsis, label, status and keywords) are deleted by ordinary navigation
**Status**: In progress

**Commit**: pending

## Evidence
`ui/src/components/inspector/Inspector.tsx`: `lastDocId` is initialised to
the selected document's id, so when the Inspector mounts with a document
already selected the hydration block never runs and every form field starts
empty; the debounced save effect runs on mount and 1.5 s later writes the
empty form (`notes: null`, and likewise `synopsis: null`, `label: null`…),
which the backend treats as "remove". Slice 3 added `notes` to that
payload; the pattern predates it.

## Predicted observable failure
Select a document with saved notes while the Inspector is hidden, open the
Inspector, wait 1.5 s: the notes (and the other metadata) are gone from the
sidecar. Reproduced by the reviewer with `fields: { notes: null }`.

## Approach
Initialise the form from the selected document on mount, and never save a
hydration: a one-shot skip flag set by the hydration path (mount included)
makes the debounce effect skip its first run, so only edits are saved.

## Guard proof
`ui/src/test/inspectorNotes.test.tsx` "mounting on an already selected
document shows its notes and saves nothing by itself": the Notes box shows
the stored notes at once, no save happens within 2 s, and an edit then
saves once with the new text. With the fix reverted (last-document id
initialised to the selection and the hydration skip removed) the test
fails; restored, all three tests pass; UI lint clean.

which the app enables in `ui/src/main.tsx`: the effect's first run records
the hydration counter and returns, the development replay sees matching
counters and schedules a save of the untouched form. Reproduced: a document
with `keywords: ["family, friends"]`, two seconds without editing, one save
with `keywords: ["family", "friends"]`. Suggested: gate saving on a
comparison against the hydrated baseline, and cover StrictMode in the
guard.

**Disposition: ADMITTED.** Repair: the effect keeps the form as last
hydrated or last saved as a baseline and saves only a form that differs
from it, so a replayed effect with the same values saves nothing; the
baseline moves when a save is dispatched, so editing back to the stored
text still saves. Guard: a StrictMode-wrapped mount saves nothing in two
seconds, an edit saves once, editing back saves again.
