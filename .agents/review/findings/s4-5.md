# s4-5: A bracket in anchor text keeps a footnote from attaching

**Severity**: MEDIUM — the footnote is demoted to an unanchored comment and vanishes from compiled output
**Status**: In progress
**Branch**: — (default-branch mode)
**Commit**: pending

Source: Reviewer (generation): codex / gpt-6-astra / xhigh / frontier (owner-named pair)
Range: 19f1c89^..19f1c89 (slice 4), codex-cli 0.164.0, 2026-10-26 00:05 UTC.

## Evidence
`attach_annotations`'s anchor pattern `\[([^\]]*)\]` cannot match a label
with an escaped `\]`; Pandoc writes `[a\] b](scrivcmt://FN-1)` for anchor
text `a] b`.

## Predicted observable failure
The link stays raw, the footnote body becomes an unanchored comment, and the
compiled footnote disappears. Reproduced by the reviewer.

## Approach
The label pattern accepts escaped characters: `(?:\\.|[^\]\\])*`.

## Files changed
- `crates/cli/src/scrivener/converter/mod.rs`

## Guard proof
`cargo test -p chikn-converter --lib -- anchor_text_with_an_escaped_bracket_attaches`:
`[a\] b](scrivcmt://FN-1)` with a footnote body → `a\] b` followed by the
footnote element, no unanchored comment, no warning. With the old pattern
the test fails; restored, it passes.
