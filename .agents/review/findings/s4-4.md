# s4-4: Inline notes lose the document's encoding

**Severity**: MEDIUM — non-Western note text is silently corrupted
**Status**: In progress
**Branch**: — (default-branch mode)
**Commit**: pending

Source: Reviewer (generation): codex / gpt-6-astra / xhigh / frontier (owner-named pair)
Range: 19f1c89^..19f1c89 (slice 4), codex-cli 0.164.0, 2026-10-26 00:05 UTC.

## Evidence
`lift_inline_notes` wraps a body in a fresh `{\rtf1\ansi …}` document, so
the declared `\ansicpgN`, default font and font table are lost.

## Predicted observable failure
In a `\ansicpg1251` document the bytes of `Привет` in a note become
`Ïðèâåò`. Reproduced by the reviewer.

## Approach
Bodies are decoded with the document's own header: the wrapper carries the
document's `\ansicpgN`, `\deffN` and font table (found by tokenizing, as
the preparer does), so hex escapes and font switches in either form decode
as they would in place.

## Files changed
- `crates/cli/src/scrivener/parser/rtf_prepare.rs`

## Guard proof
`cargo test -p chikn-converter --lib -- inline_notes_are_lifted_into_marker_fields`:
a `\ansicpg1251` body `\'cf\'f0` → `Пр`; a `\deff1` body in a `\fcharset204`
font → `П`; a body switching to that font mid-way → `café П`. With the bare
`{\rtf1\ansi …}` wrapper put back the test fails; restored, it passes.
