# s4-8: Compile rewrites footnote-shaped markup inside code examples

**Severity**: MEDIUM — document text that is not a footnote is changed on export
**Status**: In progress
**Branch**: — (default-branch mode)
**Commit**: pending

Source: Reviewer (generation): codex / gpt-6-astra / xhigh / frontier (owner-named pair)
Range: 19f1c89^..19f1c89 (slice 4), codex-cli 0.164.0, 2026-10-26 00:05 UTC.

## Evidence
`footnotes_to_references` searches the raw Markdown without regard to
fenced, indented or inline code.

## Predicted observable failure
A fenced HTML example containing a footnote-shaped `<sup>` was replaced by
`[^cs-fn2]` in HTML and DOCX exports. Reproduced by the reviewer.

## Approach
The transformation skips fenced code blocks, indented code blocks and
inline code spans.

## Files changed
- `crates/core/src/core/compile.rs`
- `crates/core/Cargo.toml`, `Cargo.lock` (repair: pulldown-cmark for core)

## Guard proof
`cargo test -p chickenscratch-core --lib -- footnote_shaped_markup_inside_code_is_left_alone`:
fenced (backtick and tilde), indented and inline code keep their
footnote-shaped markup while real footnotes around them convert; an
unmatched backtick is ordinary text. With every line routed to the prose
transform the test fails; restored, it passes.
