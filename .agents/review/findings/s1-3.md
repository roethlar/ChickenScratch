# s1-3: The fallback decodes every ANSI byte as Windows-1252

**Severity**: MEDIUM — non-Western prose becomes unreadable under a formatting-only warning
**Status**: In progress

## Evidence
`crates/cli/src/scrivener/parser/rtf_text.rs` `cp1252()` is applied to
every `\'xx` escape and every high byte regardless of the declared
`\ansicpgN`. (`rtf_prepare.rs` leaves non-1252 escapes to Pandoc, which
garbles them too: "Unsupported code page 1251".)

## Predicted observable failure
A truncated document with `\ansicpg1251` and `\'cf\'f0\'e8\'e2\'e5\'f2`
imports as `Ïðèâåò` instead of `Привет`.

## Approach
Decode by the declared code page using `encoding_rs` (already in the
dependency tree): the fallback decodes hex escapes and literal high bytes
with that encoding; the prepare step rewrites hex escapes to `\uN ?` for
every code page `encoding_rs` knows, so Pandoc never sees an unsupported
page either. Unknown pages keep the 1252 behaviour.
