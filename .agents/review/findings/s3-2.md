# s3-2: Image filenames with spaces or non-ASCII cannot display

**Severity**: MEDIUM — valid project pictures stay broken in both shells
**Status**: Verified — accepted 2026-10-27 21:48 UTC
**Branch**: — (default-branch mode: one finding ↔ one commit on `master`)
**Commit**: `103c033`

## Evidence
`ui/src/components/editor/ImageNode.ts` (`renderHTML` of `src`) and `ui/src/platform.ts` `resolveAssetUrl`. For `![Picture](<research/my image.png>)` the attribute holds the Markdown URI `research/my%20image.png`; the resolver encodes it again into `path=research%2Fmy%2520image.png`, the route decodes once and the service looks for the literal file `my%20image.png`.

## Approach
Keep the Markdown URI in the attribute for serialisation; decode it once (as a local path) before building the shell's asset URL.

Declared before repair: `ui/src/components/editor/ImageNode.ts`, `ui/src/platform.ts`, `ui/src/test/editorImportedContent.test.tsx`. Actual (per the repair review): `ImageNode.ts` and the test only; `platform.ts` needed no change.
