# s3-9: An intermediate symlink bypasses the hidden-entry guard

**Severity**: MEDIUM — the shared service leaks hidden files from both shells
**Status**: In progress — fixed, repair review pending
**Branch**: — (default-branch mode: one finding ↔ one commit on `master`)
**Commit**: `6829d4d`; repair `95570e9` after repair review 1; repair `064077b` after repair review 2

## Evidence
`crates/services/src/assets.rs` `serve_project_asset` checks only the final component for a symlink. A visible directory symlink inside the project pointing at `.git` serves `.git/config` through its alias, while `.git/config` asked directly is refused.

## Approach
Check every component on the way down with `symlink_metadata` (refuse any symlink) before opening, and open the file without following links where the platform allows.

## Files changed
Declared before repair: `crates/services/src/assets.rs`. Repair: the same file plus `crates/services/Cargo.toml` and `Cargo.lock` (libc on Unix). Repair 2: `crates/services/src/assets.rs` only.

## Guard proof
`refuses_a_symlinked_folder_on_the_way` (crates/services/src/assets.rs) fails with the per-component symlink check removed; restored → 6 passed.

Repair `064077b`: the final no-follow open carries `O_NONBLOCK` (a regular file ignores it; a pipe open returns at once and is refused as not-a-file). `a_named_pipe_is_not_found_rather_than_waited_on` (a FIFO named `pipe.png`, request run on a thread with a five-second limit) fails with `O_NONBLOCK` removed ("the request waited on the pipe instead of refusing it"), exit 101; restored → 61 services tests passed, clippy and fmt clean.

Repair `95570e9`: on Unix each folder is held open and the next entry opened relative to it with `O_NOFOLLOW` (`O_DIRECTORY` for intermediates), the file read through the final handle; a symlink on the way is still `Outside` (`fstatat` with `AT_SYMLINK_NOFOLLOW`, since Linux answers `ENOTDIR` rather than `ELOOP` when `O_DIRECTORY` is set). `a_folder_swapped_for_a_symlink_mid_request_never_serves_hidden_files` (3,000 requests while a thread flips the folder between a directory and a symlink to `.git`) fails with the path-based walk compiled in on Unix ("the hidden file leaked"), exit 101; restored → 7 asset tests and 60 services tests passed, clippy and fmt clean. New dependency: `libc` for the services crate on Unix (lockfile gains the edge only).

## Coder dispute
None.

## Known gaps
Windows keeps the path-based walk (per-component `symlink_metadata`, then canonicalise and contain): it closes the static alias but not a concurrent swap, because the standard library offers no handle-relative open there. Closing it needs handle-relative opens (NtCreateFile against a directory handle) or verifying the opened handle's final path; neither is covered by CI, whose Windows job runs only core's process tests. Recorded 2026-10-27 at the s3-9 repair.
