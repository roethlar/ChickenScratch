# s1-6: `\line` breaks render as spaces

**Severity**: LOW — addresses and verse lose their line layout in recovered documents
**Status**: In progress

## Evidence
`crates/cli/src/scrivener/parser/rtf_text.rs`: `\line` pushes a bare `\n`,
which Markdown renders as a space inside the paragraph.

## Predicted observable failure
`first\line second` imports as `first\nsecond` and renders `first second`.

## Approach
Emit a Markdown hard line break (backslash at the end of the line) for
`\line`; the test checks the Markdown and, with Pandoc present, the
rendered result.

## Files changed
- `crates/cli/src/scrivener/parser/rtf_text.rs`

## Guard proof
`cargo test -p chikn-converter --lib -- par_and_line_are_distinguished`:
`a\line b\par c` → Markdown `a\` + newline + `b`, blank line, `c`, and
with Pandoc present the rendering is `a` / `b` / blank / `c`; a trailing
break before a paragraph end is dropped; an escaped backslash at a
paragraph end is kept. With `\line` emitting a bare newline again the test
fails; restored, it passes; the suite is 55/55.
